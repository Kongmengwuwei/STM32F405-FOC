# 换回 ZH3620-1 的自动整定实测

## 实测闭环与剩余问题

复位加载后的 ±0.1 A 平均反馈为 +0.099998 / −0.100012 A，Id 均值接近零，试验与停止检查无故障、告警或命令拒绝，遥测无序号丢帧。

±5° 三段位置切换 T90 为 70.4 / 74.8 / 73.6 ms，末段均值为 +4.9980 / −5.0022 / +5.0015°，超调约 0.67–0.68°。第二段未满足 ±0.5° 连续保持 100 ms 的到位判据，不能把末段均值接近目标当作抖动已消除。

±30 rpm 三段 T90 为 158.8 / 192.8 / 92.4 ms，20 ms 尾随平均的末段均值 +32.53 / −29.44 / +32.37 rpm；超调约 24.5–28.0 rpm，各段均未满足 ±3 rpm 连续保持 100 ms。无故障/告警且未越过主机 80 rpm、3 A 实验边界，但低速纹波仍明显，不能认定速度控制表现已经合格。

ZH3620 速度模式增加兼容缩放：`r=min(1,运行时 Kpq/编译 Kp)`，速度 Kp 乘 r、Ki 乘 r²，以减小换用较低电流 Kp 后旧速度环的过强作用；位置模式不采用此缩放。这是当前已知电机的保守兼容处理，未辨识惯量、摩擦或自动求速度/位置增益。

## 本次修正与拒绝条件

- 自动扫描目标电流以 2.5 s 渐升，在 3.5 s 保持后开始双向扫描，总计 28 s，减小原电机启动冲击。
- 零点改为两个方向各两圈的平均电角度偏差，减少齿槽/静摩擦和方向滞后对单个静止零点的影响。
- R/L 注入固定定子 d/q 坐标，避免小零点误差下磁场追随转子形成持续转矩。DC 前 0.2 s 允许有界平衡位置调整（30°、120 rpm），不参与拟合；正式采集及全部 AC 阶段仍严格限制在 0.5°、20 rpm。
- 扫描与 R/L 初始化改为显式字段写入，减少关中断期间 nano-libc 逐字节清零的延迟。修正后仍有偶发 R/L 启动时序中止，尚需继续定位；没有放宽 PWM 时序阈值。

实测中出现过电流中止、回程误差拒绝、AC 拟合拒绝和时序中止。失败均关输出，未保存无效结果；工具不自动重试或自动加大电流。最终扫描、R/L、应用及保存均分别通过，复位后的闭环复测完成。主机回归覆盖 1～64 极对双方向、齿槽偏置、固定辨识坐标、DC 运动边界、RL 对象、12/18/24 V 仿真、Flash v3/v4、USB、WARN/TRIP、原 M0 与采样窗口，并完成 ZH 速度兼容缩放测试。实机本次仅验证 12 V 空载。

## 构建与复现

当前烧录文件为 `build/commission-zh3620/Debug/STM32F405-FOC.elf`。新增共享预设 `Debug-ZH3620-commission`，在 ARM 工具链与 Ninja 已配置的环境中从固件工程根目录运行：

```powershell
cmake --preset Debug-ZH3620-commission
cmake --build --preset Debug-ZH3620-commission
```

本机 `Debug-commission-zh3620` 是带安装工具链路径的本地同配置预设。原 `Debug` / `Debug-local` 仍是龙邱安装 2 档案，烧录时应选择上述 ZH3620 ELF。

从 `variants/m1-mt6835/` 运行已验证的电流设置：

```powershell
python tools/bench/autotune.py --commission --cal-current 2.00 --current 3.00 --save --out build/zh3620-commission
```

先断开 VOFA 串口占用。失败后检查阶段与错误码，不能仅反复增大电流；若扫描已应用但 R/L 失败，可保留该有效角度候选重新辨识，或复位恢复保存记录。当前记录已保存，正常使用无需每次重扫。

完整数值与失败实例见 [汇总 JSON](data/zh3620-autotune-20261010.json)。本机原始数据位于 `build/longqiu/newmotor-20261010/`，汇总保留实际烧录 ELF 的 SHA-256。最终输出已关闭，恢复 `send 6` 供原 VOFA 总览使用。
