# 现在的 FOC 怎样调试和改良

这份路线针对 M0 + TLE5012B + ZH3620-1（7 极对），按 2026-09-27 当前源码和此前实测整理。用户反馈 WARN 版本效果可以；这说明当前操作效果改善，但还不能给它一个未经测量的带宽、转矩精度或持续电流额定值。

**建议顺序：保存基线 → 确认数据 → 采样零点与增益 → 编码器与电角度 → 电流 PI → 电压饱和与抗积分饱和 → 速度估计 → 速度 PI → 位置 P → 负载、温升与拓展。** 先把前六项做扎实，符合目前优先保证电流环的目标。

## 1. 本次通信调整到底改了什么

| 项目 | 调整前 | 调整后 |
|---|---|---|
| VOFA / USB CDC 串口参数 | 2000000 | 1000000，8N1、DTR |
| M0 PWM、ADC、电流 PI | 10 kHz，100 μs 一次 | 保持 10 kHz |
| M0 USB 帧率 | 10000 帧/s | 5000 帧/s，200 μs 一帧 |
| M0 USB 数据量 | 520000 B/s | 260000 B/s |
| M1 电流环 / USB | 20 kHz / 20 kHz | 20 kHz / 10 kHz |
| USART2 | 2 Mbps，2 kHz 独立帧 | 保持原值 |

原生 USB 的波特率只是 CDC 参数，代码接收它但不据此节流。因此两件事分别实现：VOFA 设置和 CDC 默认值改为 1000000；`FOC_USB_DIVIDER=2` 使固件每两次控制采样发一帧。命令解析、采样、换相与 PI 都不会等待 USB。

帧仍为 52 字节，`send 0..5` 和 I2/I9 绑定保持。时间戳仍表示该次实际采样，序号仍计数全部电流环周期，因此正常序号差是 **2**。`capture_usb.py` 默认 M0 10 kHz、divider=2；工具判连续性时必须同时知道控制频率和分频值。

```sh
python tests/capture_usb.py COM8 --group 4 --sample-hz 10000 --usb-divider 2 --seconds 30
```

先断开 VOFA 以释放串口，再运行校验；该脚本只切遥测，不启动电机。需要观察完整 10 kHz 电流样本时，在独立构建目录用 `-DFOC_USB_DIVIDER=1`，工具对应 `--usb-divider 1`。组 0–4 每隔一次采样记录当前值；组 5 对窗口内 Id/Iq、Ud/Uq、转速和母线求平均，在目标或状态变化处重新开始，电压比例取窗口最小值。默认组 5 的一个点通常代表两次采样，边沿可能仅含一次；时间戳是窗口末端。**电流反馈没有加滤波**。平均只能减轻遥测混叠，高频纹波仍须用 divider=1 记录，不能根据曲线变平滑就判定电流更稳。

VOFA 的横轴采样间隔应为 **0.2 ms**。若界面不能输入小数，改用样本点判断或导出记录，按帧内时间戳计算；不要把 1 ms 的图表标尺当作真实的控制响应时间。

## 2. 程序已经具备哪些基础

```text
ASCII 目标 → 命令解析 / 控制模式
                       │
        位置 P → 速度 PI（1 kHz）
                       │ Iq_ref
TLE5012B 角度 ──┐      ▼
B/C 两相 ADC ───┴→ Clarke / Park → Id、Iq
                                  │
                         Id_ref=0、Iq_ref−Iq
                                  ▼
                             d/q 电流 PI
                                  ▼
                    电压饱和 → 逆 Park → SVPWM
                                  ▼
                        TIM1 三相互补 PWM

USB 只旁路记录计算结果：M0 5 kHz，不参与闭环调度。
```

电流模式下 `Iq` 直接决定 q 轴目标。它控制转矩，不决定转速；空载时会加速。`rpm` 和 `pos` 则通过外环产生 Iq。测试电流环时不要混用 `rpm`，否则 I2 是速度环给出的目标，观察到的慢变化不能全归因于电流 PI。

| 当前参数 | 值与实际含义 |
|---|---|
| 电流比例 Kp | `0.20 V/A`，位于 `foc_motor.h` |
| 电流积分 Ki | `24 V/(A·s)`，每 100 μs 增量系数为 `0.0024 V/A`；本轮从 20 小幅整定 |
| 两相电流换算 | `(采样电压−零偏) × 50 A/V`，增益仍未外部标定 |
| ADC 参考电压 | M0 配置 `3.13 V`，需要与实际 VDDA 对照 |
| 绕组电阻 | 暂定 `0.12 Ω`；两线表扣除表笔后的粗估只支持数量级 |
| 电感、磁链 | 均为 0，当前关闭交叉解耦和反电势前馈 |
| 编码器方向 | 当前安装已存方向 −1，不能据此说接线错误 |
| 速度滤波 | TLE5012B `alpha=0.02`，在 10 kHz 下时间尺度约 5 ms |
| 运行策略 | WARN：阈值只告警，目标保持到新命令或 stop |

此前 ±0.10/±0.20 A 短测的内部电流均值跟随目标，Id 均值接近零；但单样本误差有明显高频波动，正负向不完全一致。断开电机也曾测到偏置，PWM 开启后的校零减小了均值误差。这使**采样质量与相位**成为当前优先排查项。详细数值在[历史诊断记录](zh3620-1-live-diagnosis-2026-09-24.md)，不能全部当作新 WARN 版本的实测指标。

## 3. 按顺序怎么做

### 第一步：保存现在能运行的基线

记录 Git 版本、构建组合、安装编号、WARN/TRIP、USB divider、Kp/Ki、供电电压、输入限流设置、校准记录和接线照片。用同一套短测试记录正负小电流，保存原始数据。以后每次只改一个参数，使用同样的目标和观察窗口比较。

推荐基线是当前能稳定执行的 ±0.10 A、±0.20 A；用户确认效果改善的范围可以追加。这里不自动新增高电流试验，也不把图片的 12 A 堵转参数当作连续目标。

**进入下一步的依据：** 同样的目标能重复进入 RUN、改变目标及 stop，原始文件知道何时发了什么命令。WARN 告警记下来，不用反复 clear 隐藏过程。

### 第二步：先把记录的时间与状态看对

用 `send 4` 看 I2/I9；同时记录 I6 状态、I7 转速、I10 停止原因、I11 母线、I4 告警。5000 帧/s、时间差约 200 μs、序号差 2 是正常情况；不要修改电流 PI 来“修复”图表时间轴或接收丢帧。

首次从待机启动有约 **2 ms 预充 + 1 ms PWM 校零等待 + 50 ms PWM 校零采集**，约 53 ms 后才进入 RUN。这是启动流程。要测 PI 阶跃响应，应在已经 RUN 时改变 Iq，从 I2 真正变化的那个采样开始计时。

**进入下一步的依据：** 数据连续且状态含义确定；USB 帧率改变不造成电流环周期改变。若 TIMING 或 ADC 告警新增，优先看 `motor_period_min/max`、`motor_work_max`、`motor_write_min` 和 ADC 错误计数。M0 名义每周期约 16800 个 CPU 周期；最坏耗时还须满足实际 PWM 提交窗口，不能只以小于 100 μs 判断合格。

### 第三步：把采样零点、增益和极性弄可靠

先比较关断时与等占空比 PWM 时的 B/C 零点、均值、标准差和尖峰。在无实际绕组电流的对照条件下，计算电流应围绕零，不能固定偏到一侧。`send 0` 看原始码和电压，`send 1` 看 ib/ic、零偏、积分器和 Ud/Uq。

再核对采样电阻、运放增益及两相极性，采用可验证的外部电流参考校准比例。实验电源面板显示的母线电流不能直接拿来标定某一相或 Iq：PWM 桥内相电流与直流输入电流不是同一个量。现在没有示波器时，仍能做零偏统计、手转编码器和短时均值对照；逐 PWM 纹波、死区和尖峰根因仍需后续波形测量。

**进入下一步的依据：** 零偏在多次上电和开启 PWM 后可重复；正负电流比例有独立依据。如果两相增益不同，将共用 `FOC_CURRENT_A_PER_V` 改为两相各自的增益/极性配置，避免用 PI 吸收测量误差。不要先给电流反馈加大低通滤波以使曲线好看，滤波会改变环路延迟。

### 第四步：确认角度和电角度校准

检查 TLE5012B 错误计数在静止、手转以及 PWM 运行时是否新增。机械转一圈应连续跨越 0/360°；改变三相接线或磁铁安装后更新安装编号并重新 cal。

7 极对的一电周机械行程约 51.4°。对齐应正反走完并回到起点附近，重复校准的零点应接近；Id 的均值应接近 0，正负 Iq 的实际转矩方向应相反。若零点错，PI 可能让“计算 Iq”跟上，却把一部分电流送到错误方向，所以 Id 也要看。当前 USB 组 1 没有直接 Id 通道，组 3/4 也没有；可用 UART 的 Id/Iq 帧，或按同一组 1 样本的 ib/ic 和电角度离线重算。

**进入下一步的依据：** 不靠重插或复位偶然恢复；角度、相序和零点可重复。对当前成功校准先留备份，无须为了每次 PI 修改重做 cal。

### 第五步：只调电流 PI

保持电压、采样点、编码器和校准不变。采用短时、可重复的正负小幅目标变化：0 → 0.10 → 0.20 → 0，再做负方向对照；每段主动 stop。空载目标不要长时间保持，否则转速、反电势都在变化，难以比较两次 PI 调参。更严格的低速阶跃测试可使用合适的负载/固定夹具，不能用手攥住电机轴。

记录四类指标：

1. Iq 误差均值：是否长期偏离目标。
2. Iq 误差 RMS、标准差、峰值：是否有振荡和尖峰；原始数据与 1 ms 统计分别报告。
3. 上升时间、超调与稳定时间：从 RUN 内 I2 的阶跃开始计算，时间用帧时间戳。
4. Id 均值与波动、Ud/Uq 饱和：排除换相误差和电压能力不足。

没有电感实测值时，先保留当前 Kp/Ki 为对照。若需要探索，可暂时减小或设零 Ki，在小幅阶跃下以约 10%～20% 的幅度改变 Kp，找到响应更快且没有持续振荡的区域，再逐步增加 Ki 消除稳态误差。每次都回到同样的初始条件，禁止同时加大 Kp、Ki 和目标电流。此百分比是本项目的试验步幅建议，不是电机额定参数。

若测得有效相电阻 R 和电感 L，可用低速 RL 模型的并联 PI 初值：

```text
omega_c = 2*pi*目标电流带宽_Hz
Kp = L * omega_c
Ki_per_s = R * omega_c
Ki_step = Ki_per_s / FOC_SAMPLE_HZ
```

这是把绕组模型 `1/(L*s+R)` 的极点与 PI 零点配对后的初值推导，依据 [TI 电流 PI 设计说明](https://www.ti.com/document-viewer/lit/html/SSZTCG4/GUID-4EBDE243-F8EA-41D6-8930-1E6BFACE8DEE)，适用前提是本项目的电压输出/电流反馈单位、低速反电势近似及正确参数。实际还存在采样、运放、编码器与 PWM 延迟；**10 kHz 控制频率不等于 10 kHz 闭环带宽**。L 未测时不提供一个看似精确的最终 PI 值，也不要搬参考电机的 50 μH。

**进入下一步的依据：** 正负方向的小幅阶跃可重复、没有持续振荡，Iq 均值误差和纹波达到自己明确写下的测试目标。目标精度须结合标定和噪声，例如可先观察均值误差能否在几百分之一安培内重复，再按实际能力收紧；这不是当前固件已达到的承诺。

### 第六步：处理饱和和正负不对称，再考虑解耦

VOLTAGE 告警表示请求电压超过线性调制或采样窗口能力，出现时“目标跟不上”不一定是 Ki 太小。先区分供电不足、转速产生反电势和窗口限制。当前已取消 M0 人为的 10% 电压上限，物理电压约束仍存在。

旧电流 PI 回算把电机电阻同时用作回算系数，这是历史实现的调试耦合点：本轮已改为独立 `FOC_MOTOR_CURRENT_AW_PER_S * Ts`，ZH 默认 1200/s，使电阻辨识不会顺便改变饱和恢复速度。WARN 下速度积分也没有电流限幅，未来调外环时应通过实际可执行的电流/电压能力回算，避免饱和后积分长期累积；这属于控制器调节能力，不必重新引入越限锁定。

先测试目标下降至零、正负反向和饱和解除时是否迅速恢复。之后再用实测 L、磁链逐项启用 d/q 交叉解耦、反电势前馈，最后检查编码器内部角度延迟。TLE5012B 当前 `encoder_sample_delay=0` 是未标定占位值，不能当作真实零延迟。没有示波器或合适参考时，高速相位修正只应保留为待测项目。

**进入下一步的依据：** 没有长时间拖尾、反向冲击或正负方向明显不一致；能力不足时的行为能解释。

### 第七步：速度估计 → 速度 PI

先看编码器速度在静止时的噪声、低速量化、高速方向和反转迟滞，再选速度滤波。当前 0.02 的逐周期滤波与 10 kHz 配套；以后改 PWM 频率时，应按目标滤波时间常数换算 alpha。

电流环已经合格后，再从小速度目标开始调比例，随后加积分；速度环的有效带宽应明显低于电流环。`1 kHz 外环调度`只是计算频率，不代表速度带宽。持续摆动时先确认电流 PI 和机械响应，再处理速度 PI；厂家调试指南也将电流环与速度环分开调试，见 [TI MSPM0 FOC 指南第 6.2.3 节](https://www.ti.com/lit/pdf/slau948)。

当前校准方向 −1 时，速度控制代码会换算正负 Iq，这是正常的坐标映射。不要为了让“正电流等于正机械转速”反复改相线并使已有校准失效。

### 第八步：位置 P → 负载和持续能力

速度环稳定后再做小角度定位、往返、多圈和零点测试，先调位置 P；位置目标宜使用可配置速度/加速度轨迹，让电机知道怎样到达目标。然后逐级增加负载和运行时间，测温升、实际电流、机械噪声、供电跌落及运行效率。仍采用 WARN 记录异常并由试验主动停止；不要仅根据空载运行顺畅给出持续电流额定值。

## 4. 程序整理应分哪几步

当前的接口、编码器、电机、安装编号、WARN/TRIP 已独立，新增型号可在配置和驱动层扩展，不用复制控制算法。这次又独立了 `foc_telemetry.h`，使 USB 帧率不再与电流环固定绑定。

后续按以下小步拆分，每步先保存基线再迁移，不同时更改 PI 算法：

| 优先级 | 改良 | 原因与检查方法 |
|---|---|---|
| 1 | 增加命令接受结果、USB 组内可读构建信息和最新告警时间 | 目前只有累计拒绝次数，不能直接区分语法错、未校准或状态不允许；二进制 USB 中不能随意混入 ASCII ACK |
| 2 | 分离采样校准参数、记录有效性和控制输入快照 | 两相增益/极性、PWM 零偏和电角度属于不同对象；把 Id/Iq、角度、采样身份放在同一快照，避免离线混组 |
| 3 | 从 `foc.c` 拆出 current_loop、modulation、alignment；从 `app.c` 拆出 command 与 telemetry | 目前大文件同时处理校准/状态/数学和通信/Flash，单独测试与新增功能容易相互影响 |
| 4 | 电流 d/q 和速度 PI 共用带独立抗饱和参数的控制器组件 | 参数单位明确，电阻辨识不修改回算，避免重复写 PI |
| 5 | 增加仅待机可写的运行参数、参数版本与保存命令 | 当前 Kp/Ki 必须编译烧录；已有命令不支持在线调参。参数更换不应抹掉安装校准，也不应在一个采样中读到半组新参数 |
| 6 | 标准化实验记录：帧时间、目标、实际、Id、饱和、告警及参数快照 | 参数改良靠同条件数据比较；不要用不同组、不同运行的数据冒充同一时刻 |

这些是待做的改良顺序，本轮已完成通信分频、M0 窗口预算、独立抗饱和系数、组 5 遥测和小电流 PI 对照；实测结果见[本轮报告](current-debug-2026-09-27.md)。最值得先开展的下一项是**可重复的短时电流阶跃记录，同时补齐 Id 与饱和信息**；得到数据后再决定调 Kp/Ki，或者先修采样。
