# AS5600 只读通信验收

本阶段不配置 TIM1/TIM8 PWM，也不输出电机转矩。按随板资料，M0 编码器接口 A=PB4/SCL、B=PB5/SDA，使用外部 3.3 kΩ 上拉；请按实物接口丝印确认 3.3 V、GND 与模块供电，避免模块自带 5 V 上拉作用到 MCU 引脚。

启动后程序每 2 ms 尝试读取 AS5600 的 STATUS 和 RAW_ANGLE。用 SWD 调试器观察 `main.c` 中以下变量：

| 变量 | 预期含义 |
| --- | --- |
| `g_as5600_bus_ready` | PB4/PB5 已初始化且总线空闲；不表示传感器已经应答 |
| `g_as5600_sample_valid` | 最近一次状态和角度读取均有效 |
| `g_as5600_raw_angle` | 0–4095；缓慢手转电机时应连续变化并在一圈后回到起点 |
| `g_as5600_magnet_status` | bit5=磁铁检出，bit4=过弱，bit3=过强；正常时至少 bit5=1、bit4/3=0 |
| `g_as5600_last_result` | 0=成功，1=总线错误，2=磁场错误，3=数据错误 |
| `g_as5600_ok_count` / `g_as5600_error_count` | 成功/失败累计次数；错误不应持续增加 |
| `g_as5600_last_read_us` | 上一次状态加角度读取耗时；用于确认软件 I²C 的实际周期 |
| `g_as5600_diag_valid` | 100 ms 一次的原始寄存器诊断读取是否成功 |
| `g_as5600_diag_raw_angle_word` | 直接读取的 RAW_ANGLE 两字节；只供排查，不可用于电机闭环 |
| `g_as5600_diag_agc` / `g_as5600_diag_magnitude_word` | AS5600 的自动增益和磁场幅值原始寄存器 |

若出现总线错误，程序保持输出关闭并每秒重新初始化软件 I²C。角度读取尚未接入闭环；下一步需实测一圈计数方向、磁铁状态、数据更新率和延迟，再进入电角度零位标定。

[AS5600 官方数据手册](https://look.ams-osram.com/m/7059eac7531a86fd/original/AS5600-DS000365.pdf)规定 I²C 地址 0x36，RAW_ANGLE 在 0x0C/0x0D，STATUS 在 0x0B。

## 2026-09-23 首次上板结果

VS Code STM32 扩展的 CubeProgrammer 经 ST-Link 识别到 STM32F405 系列，目标电压约 3.10 V；固件烧录后回读验证通过，核心持续运行。I²C 诊断寄存器读取成功，但 `STATUS=0x33`，其中 MD=1、ML=1，表示检出磁铁但磁场过弱。`AGC=0x80`、`MAGNITUDE=0x0279`，诊断 RAW_ANGLE 读到约 `0x0786–0x0787`。由于磁场状态异常，正式角度样本仍被拒绝，`g_as5600_ok_count=0`，错误计数持续增加。应先检查磁铁安装位置、中心对齐、气隙和供电，再验证缓慢手转一圈时原始角度是否连续变化；此时不能进入电机闭环。

通过 SWD 读取 GPIO 寄存器确认 M0/M1 的 12 路驱动输入均为普通输出模式且输出值为低；TIM1/TIM8 未使能。

随后手动转动 M0 轴时，诊断角度观察到 `0x08DD → 0x081E → 0x017E → 0x0C63` 等变化，说明传感器能感知轴运动。但 `STATUS` 始终为 `0x33`、`AGC` 始终为 `0x80`，有效角度计数仍为零；期间软件 I²C 一度进入重试状态，数秒后恢复。手转数据只能证明原始读数会变，尚未证明一圈单调性、方向、零位或可靠性。待检查并调整实物后复测。

## 同日再次复测

首次读取仍为 `STATUS=0x33`、`AGC=0x80`、有效角度计数零。随后 ST-Link USB 探针失去通信；重新插拔 USB 后恢复。恢复后的约 5 秒连续采样中，`STATUS` 一直为 `0x33`，`AGC` 一直为 `0x80`，`MAGNITUDE` 为 `0x026E–0x0270`，静止原始角度为 `0x09F3–0x09F4`；正式角度成功次数仍为零，错误次数持续增加。连续采样期间 I²C 诊断读数正常，未再次看到总线恢复事件。磁场过弱问题仍未排除，不应启用闭环。
