# 用 VOFA+ 查看 USB 遥测

这份说明按项目默认的 **M0 + TLE5012B + ZH3620-1** 遥测格式编写，并在本机用 **COM8、VOFA+ 1.3.10** 验证了 USB 收数与图表。USB 连通并收到数据，只证明通信和遥测正在工作；电机驱动与闭环控制还要按[首测清单](zh3620-1-first-test.md)单独验证。

## 打开连接

1. 用数据线连接开发板的原生 USB 口，给板正常供电，确保程序没有停在调试断点。
2. 在 VOFA+ 的“协议与连接”中选 **JustFloat → 串口 → COM8**；串口参数选 **1000000、8 数据位、无校验、1 停止位、无流控**。USB CDC 的波特率是上位机端设置，不决定 USB 线速。
3. 点击左上方的连接按钮，再打开下方的 **DTR**。右侧出现 `I0` 到 `I11` 且数字持续更新，就表示收到了固件的二进制遥测。若 COM 号发生变化，改选新端口。
4. 需要完整的电压/角度和电流环双标签布局时，点击画布右上角 `⋮` →“载入...”，选同目录的 [vofa-foc-current.tabview.json](vofa-foc-current.tabview.json)。只想在当前窗口添加电流环标签时，选 [vofa-current.tab.json](vofa-current.tab.json)；原来的单独双图标签仍可从 [vofa-foc.tab.json](vofa-foc.tab.json) 加载。

VOFA 的接收文本区显示乱码是正常的：固件发送的是 JustFloat 二进制帧，不是文字。连接时 COM8 被 VOFA 独占，其他串口软件须先断开 VOFA 才能使用它。

## 当前图表怎么看

在下方发送框输入 `send 0`，保持右侧换行选项为 `\n`，点击“发送”。这条命令只选择**第 0 组遥测**，不会启动电机。当前布局的两张图分别绑定：

| 图表 | VOFA 通道 | 第 0 组含义 | 纵轴 |
|---|---|---|---|
| 上图 | `I7` | 母线电压 `v_bus` | 0–20 V |
| 下图 | `I8` | 编码器原始机械角度 `angle_raw_deg` | 0–360° |

本机连接后已看到母线约 **11.37–11.39 V**，角度约 **7.7°**，两张图也持续绘制。用手缓慢转动未使能的电机轴时，可观察角度是否变化；跨过 360°/0° 时曲线会跳回起点。

`I0`、`I1` 装的是按位编码的时间、状态和序号，不适合直接当普通浮点曲线。`send 1`、`send 2`、`send 3` 会改变 `I2`–`I11` 的含义；切换后这份布局的 `I7`、`I8` 标注不再适用。各组通道表见[台架工具说明](../variants/m1-mt6835/tools/bench/README.md)。

若数字有变化而图像暂时看着平直，先看纵轴量程：静止时电压和角度本来就接近常数。这个布局的角度轴覆盖完整一圈，小幅手动转动只会表现为细小变化。

## 在同一网格比较目标和实际电流

当前推荐 `send 5`，I2/I9 绑定沿用。默认每 0.2 ms 一帧，Id/Iq 等是窗口内两个控制样本的平均，目标或状态变化时重开窗口；电流环反馈仍使用原始 10 kHz 样本。I4=Id、I5=Ud、I6=Uq、I7=转速、I8=窗口最小电压比例（1=未饱和）、I10=累计告警、I11=母线。诊断命令拒绝和停止原因时改发 `send 4`。

本机 VOFA 1.3.10 的 Δt 若只接受整数，请用点数或导出的帧时间戳计时：5 点=1 ms；不要用默认 1 ms/点直接测带宽。

打开“FOC 电流环：目标与实测 Iq”标签，在发送框发送 `send 5`，换行仍选 `\n`。这个命令只切换遥测，不会使能电机。单张网格图同时显示 `I2`（目标 `Iq_ref`）和 `I9`（内部计算的实际 `Iq`），共用 **-0.6～+0.6 A** 纵轴，便于直接看跟踪误差。当前实机已验证 COM8 收到第 3 组数据并实时刷新图表；待机时目标为 0 A，目标线可能与 0 轴重合，实测线会在零附近波动。

点击回“FOC 电压与角度”标签后，发送 `send 0` 才能让它的 `I7`/`I8` 再次对应母线电压和原始角度。**切换标签本身不会改变固件的遥测组。**

## 默认告警模式下发送电流

2026-09-27 的新版本默认 `FOC_PROTECTION=WARN`。**重新烧录后才生效**；旧板上程序仍可能有原保护。现在单次 `Iq 0.10` 会保持目标，后续 `Iq 0.20`、`Iq 0.40` 可以直接改变目标，不需要每 100 ms 重发。详细策略、告警表和仍需处理的无效数据见[台架告警模式](bench-warning-mode.md)。

1. 若右下角是红色“终止”，先停止旧的连续发送，再从箭头菜单取消连续发送，使用普通“发送(S)”。按钮仅写着“连续发送(S)”表示选择了该模式，尚未启动；输入框换文字也不能证明旧的重发已停止。
2. 单次发送 `send 4`，换行选真实 `\n`。现有电流网格仍显示 I2 目标和 I9 实测；I4 告警掩码、I5 最近新增告警编号、I6 状态（4=运行）、I8 命令拒绝次数、I10 当前停止原因（0=无）可直接看数字。
3. 单次发送选定的 `Iq` 目标，观察电流曲线和轴的运动。目标直接进入电流环，取消原 1 A/s 斜坡；测试较大电流时调大图表的 ±0.6 A 纵轴。
4. 结束时单次发送 `stop`。`Iq 0` 是零转矩，关闭串口或停止重发都不会自动关 PWM。需要清告警时再发送 `clear`；正常运行中 `clear` 只清告警，不能替代 `stop`。

电流目标控制转矩，空载会持续加速；取消超速跳闸后应主动停止。内部计算的安培数仍未外部标定，旧版只完成了短时 ±0.10/±0.20 A 跟踪验证，2026-09-27 已完成 WARN 小电流短测，见[电流采样与调试记录](current-sampling-noise.md)。

### 为什么旧版本发完又没反应

旧版本 M0/ZH3620-1 把 Iq 限制为 ±0.30 A，所以 `Iq 0.40` 被拒绝；单次命令超过 200 ms 会锁存故障 7，持续转矩超过 1000 rpm 会锁存故障 11，后续目标被锁定状态拒绝。2026-09-25 曾实际读取到故障 11。USB 无文本 ACK，因此看起来像没有收到命令。

新 WARN 版本已取消这些拒绝/锁定条件；超过原阈值只累计告警。若新版本 I8 仍增加，检查命令大小写、空格、真实换行、最多两位小数，以及当前是否已完成校零和匹配安装的电角度校准。若 I10 非零，查看对应传感器/ADC/数值问题；数据恢复后回到待机，再发新目标。不要将丢失角度后的停止误认为限流。

## 速度与位置控制（2026-09-27 调试版）

发送 `send 3`，在速度网格叠加 I8 目标、I6 实际（rpm）；在位置网格叠加 I5 目标、I4 实际（机械度）。`rpm 20` 持续正转，`rpm -20` 平滑反转；停机后 `zero` 设置位置原点，再 `pos 15` 定位并保持。`hold` 捕获当前位置并保持，`stop` 解除保持并关闭输出。

`rpm 0` 是零速度控制，没有固定位置目标；`pos 0` 是回到设定零点并保持。单次命令保持，不需要连续重发，正常静默不再记为通信超时。实测效果、当前参数、图表通道和剩余低速波动见[速度环与位置环调试记录](speed-position-debug-2026-09-27.md)。
