# 台架告警模式：电流命令持续有效，越限只记录

默认 `FOC_PROTECTION=WARN`，适用于所有接口、编码器和电机组合。电流采样结果见[电流采样与调参](current-sampling-noise.md)，最新外环行为见[带臂定位提速](position-speedup-and-foc-roadmap-2026-09-28.md)。

## 1. 修改后的行为

| 项目 | 默认 WARN 行为 | 可选 TRIP 行为 |
|---|---|---|
| `Iq` 目标超出接口/电机配置值 | 接受有限数值，记录 CURRENT；取消原 ±0.30 A 拒绝 | 拒绝超范围目标 |
| 相电流、转速、母线超出配置范围 | 记录告警，继续运行 | 停机并锁存故障 |
| 超过 200 ms 未收到新目标 | 持续保持目标，正常静默不记为 UART 告警 | 三种模式均停机并锁存 |
| 编码器角度步进大于合理性阈值 | 记录 SENSOR，继续使用有限角度 | 停机并锁存 |
| 零偏均值、噪声或 PWM 零偏变化异常 | 记录 ZERO，使用测得的零偏继续 | 终止校零并锁存 |
| 电流命令变化 | 下一电流周期直接使用新目标，无原 1 A/s 斜坡 | 保留 1 A/s 斜坡 |
| M0 普通运行电压 | 取消原 10% 母线测试上限，使用线性 SVPWM 电压能力 | 使用接口配置的测试上限 |
| 外环电流阈值 | 记录告警，不裁剪；下游电压饱和时阻止继续积分 | 保留配置上限 |
| 位置逼近速度与加减速 | 按电机轨迹参数规划速度，不停止、不拒绝位置目标；直接 Iq 不经过速度规划 | 同样规划，另保留阈值策略 |
| 采样周期或 PWM 提交迟到 | 记录 TIMING，未成功提交时保持上一完整 PWM 周期 | 停机并锁存 |
| UART 接收出错 | 丢弃损坏的命令行、记录 UART；保留已执行目标 | 运行中停机并锁存 |
| USB 遥测缓冲满 | 丢弃新的整帧，腾出空间后自动恢复 | 遥测溢出锁存，需 USB 复位 |
| 校准 Flash 保存失败 | 记录 FLASH，使用有效 RAM 校准至下次复位 | 锁存故障 |

配置头文件中的数值仍用于产生告警和选择 TRIP 行为，不再是 WARN 下的运行许可门槛。电机名称、极对数、PI 参数、安装编号和校准记录格式保持原有含义。WARN 下没有软件温度或持续电流额定值判断，也没有软件超速关断。

## 2. 仍然需要的计算条件

电流环每周期必须得到转子角度、两相电流和正的母线电压，才能计算下一组 PWM。以下条件无法靠外部电源修复，因此仍有明确处理：

- 编码器角度为 NaN、ADC 数据无效或转换未完成、母线为零/负数/非有限数、计算溢出、生成的 PWM 不可表示：停止输出并记录原因。WARN 在下一次有效采样后自动回到待机，不恢复旧转矩；再发新目标即可，无需等待原来的越限锁定条件。
- 三相占空比必须落在定时器有效范围内，并留出低边采样窗口；SVPWM 的物理电压饱和和电流 PI 抗积分饱和仍然工作。无法达到电流目标时记录 VOLTAGE，不能通过删除这类边界让电源产生不存在的电压。
- 驱动死区、启动时低边预充、上电电流零偏采集保持。它们决定六管驱动和电流测量的基本时序。
- `cal` 的电流/电压是校准扫描的激励参数，仍为 0.45 A/0.20 V；它们不限制普通 Iq 命令。可选 Capture 构建在采满 2048 点后结束本次捕获并停机，这仍是有限时长试验本身的结束条件。
- 必须有匹配当前接口/电机/编码器/安装编号的电角度校准。扫描行程或回位不合格时记录 ALIGNMENT 并结束本次校准，保留已有有效校准，不把失败数据写成有效记录。无有效校准时先运行 `cal`。
- 外设初始化失败或处理器进入不可恢复的错误处理时，程序无法继续正常控制，仍保持输出关闭。

这些情况和一般越限分开处理。WARN 的电流、转速、母线阈值告警不会触发上述停止。

## 3. VOFA 操作

重新烧录本版后，VOFA 保持 JustFloat、实际 COM 口、1000000、8N1、DTR 开启，命令末尾选择真实 `\n`。选择单次发送；若按钮是红色“终止”，先停止旧的连续发送。

逐条发送：

```text
send 4
Iq 0.10
Iq 0.20
Iq 0.40
stop
clear
```

这是命令格式示例，不是要求按顺序自动连续运行。每次改变电流都先看响应。`Iq 0.40` 现在会执行，而不会被 ±0.30 A 规则拒绝。单次目标会一直保持，**停止 VOFA 重发、关闭串口、拔 USB 都不会替代 `stop`**。`Iq 0` 是零转矩目标，`stop` 才关闭功率级。

`send 4` 兼容现有电流网格：

| VOFA 通道 | 含义 |
|---|---|
| I2 | 真正进入电流 PI 的目标 Iq_ref，A |
| I3 | 最后接受的 Iq 命令，A |
| I4 | 告警位掩码，每个原因对应 `1 << 编号`，一直累计至 clear/复位 |
| I5 | 最近新增的告警编号；重复已有告警不会反复刷新 |
| I6 | 普通数值状态：0 待机、1 预充、2 校准、3 保存、4 运行、5 无法计算、6 校零、7 PWM 校零 |
| I7 | 编码器滤波转速，rpm |
| I8 | 累计拒绝命令行数；语法错、尚未校准等仍会拒绝 |
| I9 | 内部计算的实际 Iq，A |
| I10 | 当前停止原因，0 表示没有停止原因 |
| I11 | 母线电压，V |

I0/I1 仍是按位编码的时间/状态/序号，帧仍是 52 字节。原来的 `send 3` 继续可用。现有电流图纵轴是 ±0.6 A，测试更大电流时调整纵轴，避免曲线跑出显示范围。

告警编号：1 SENSOR、2 ADC、3 TIMING、4 WINDOW、5 ALIGNMENT、6 FLASH、7 UART、8 BUS、9 ZERO、10 CURRENT、11 SPEED、12 POSITION、13 NUMERIC、14 VOLTAGE。例如 I4=1152 表示 UART 与 CURRENT 两个原因：`128 + 1024`。`clear` 在正常运行时只清告警，**不会停止当前目标**；结束试验先 `stop` 再 `clear`。命令拒绝和 USB 丢帧统计不随 `clear` 重置。RAM 中 `foc.warning_count` 是本轮出现过的不同告警原因数。

## 4. 配置和代码结构

在固件 CMake 目录执行：

```sh
cmake --preset Debug-local -DFOC_PROTECTION=WARN
cmake --build --preset Debug-local
```

输出 `build/Debug/STM32F405-FOC.elf`。需要旧的跳闸策略时，使用独立目录配置 `-DFOC_PROTECTION=TRIP`。构建日志会打印 `protection=WARN/TRIP`，USART2 的 `hello` 也会报告 `policy`。既有 v3 校准记录不因策略切换而失效。

| 文件 | 职责 |
|---|---|
| `App/Config/foc_policy.h` | 共用策略和可选电流斜坡；与型号选择独立 |
| `App/FOC/foc.c` | `foc_warn` 记录、`foc_check` 阈值策略、`foc_trip` 不可计算的停止；电流 PI/SVPWM |
| `App/Control/control.c` | 命令保持、模式切换、外环；WARN 不再因超时失去更新能力 |
| `App/Control/app.c` | 命令语法、告警遥测组、clear、采样提交及 Flash 失败处理 |
| `App/Hardware/bsp/bsp_motor.c` | 保证完整 PWM 提交，迟到周期按策略处理 |
| `App/Hardware/bsp/bsp_usb.c` | 保持发送缓冲所有权，WARN 溢出后可恢复 |

## 5. 本次验证与仍未确定的问题

真实 app/control/foc 主机测试覆盖：`Iq 0.40` 接受、超过 200 ms 仍运行、相电流/转速/母线/角度步进同时超阈值仍不锁存、新电流立即生效、告警清除、无效编码器停止及有效数据恢复待机。WARN/TRIP 两种策略均测试；USB 测试验证整帧丢弃后恢复、缓冲不覆盖正在发送的数据。主机测试无法验证电机温升、驱动波形或实际相电流。

外部实验电源限制的是直流输入侧电流；桥内相电流和母线电容提供的瞬态能量不能等同于电源面板读数。已知尚未解决：采样增益/极性未外部标定，EG2134 栅极和 ADC 窗口未示波验收，ZH3620-1 的实测绕组参数尚未完整整理。速度/位置环已在约 12 V 的塑料臂短测中调参，但长期温升和不同负载仍未验收。空载恒定 Iq 会持续加速，取消超速关断后需主动观察并发送 `stop`。告警模式取消测试阻拦，不代表这些问题已经修复。
