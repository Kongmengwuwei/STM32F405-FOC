# 文件导览：每个文件在工程里做什么

先读[教学主文档](FOC-从零读懂这个工程.md)，再按本页找代码。下表把同一模块的 `.c` 和 `.h` 放在同一行：**`.c` 是函数实现，`.h` 是外部接口、类型与常量声明**；因此两个文件的职责都在该行说明。标为“厂商库”的文件随参考工程原样提供，用来支撑构建，初学者不必逐行通读。空的 `.gitkeep` 仅用于保留目录，不含程序。

## A. 应用代码：最应该读的文件

| 文件（相对于固件根目录） | 作用与阅读重点 |
|---|---|
| `App/Control/app.c` / `app.h` | 应用总调度接口：初始化外设驱动、20 kHz 采样回调、UART/USB 命令解析、日志封装、故障入口、Flash 保存与采集恢复。`app_sample()` 是从采样数据进入 FOC 的桥梁。 |
| `App/Control/control.c` / `control.h` | 1 kHz 速度 PI 与位置 P 级联、目标发布、模式切换、多圈相对位置、主机 200 ms 看门狗。输出为电流环的 `Iq_ref`。 |
| `App/FOC/foc.c` / `foc.h` | 核心控制：角度修正、零偏、Clarke/Park、双电流 PI、前馈、逆 Park、SVPWM、采样窗口、自动校准和状态机；头文件定义状态、故障、控制数据与阈值。 |
| `App/FOC/sine_table.inc` | 供 `foc.c` 包含的正弦查表数据。512 个区间加终点，用插值快速算正弦/余弦；它不是独立编译单元。 |
| `App/Hardware/bsp/bsp_adc.c` / `bsp_adc.h` | 配置 TIM8 触发的双 ADC、DMA2 Stream0；检查采样错误，发布 B/C 相及母线电压和原始码值。头文件定义三路快照和只读统计接口。 |
| `App/Hardware/bsp/bsp_motor.c` / `bsp_motor.h` | 电机功率安全边界：TIM8 三相互补 PWM、预充、关断、谷底更新、截止检查、采样时间戳、周期统计、Flash 校准读写。头文件定义 OFF/PRECHARGE/PWM 模式与状态接口。 |
| `App/Hardware/bsp/bsp_motor_record.h` | Flash 扇区 11 的记录格式、FNV 式校验和与有效性检查；`magic`、版本、7 极对、方向和零点共同决定记录能否复用。 |
| `App/Hardware/bsp/bsp_uart.c` / `bsp_uart.h` | USART2 2 Mbps：TX 双缓冲 DMA、RX 字节中断与环形队列、错误计数、毫秒时间接口。头文件规定非阻塞写入与队列容量。 |
| `App/Hardware/bsp/bsp_usb.c` / `bsp_usb.h` | USB CDC 的 64 KiB 发送环、发送完成回收、DTR 会话、接收背压、溢出锁存和统计。头文件是应用与 USB 回调之间的接口。 |
| `App/Hardware/bsp/bsp_can.c` / `bsp_can.h` | CAN1 初始化、非阻塞发送、15 帧有效接收队列及丢帧计数。当前应用没有用 CAN 控制电机。 |
| `App/Hardware/mt6835/mt6835.c` / `mt6835.h` | 与 MCU 无关的 6 字节 MT6835 帧解码：CRC、状态位和 21 位原始角度转机械角；错误返回 NaN。 |
| `App/Hardware/mt6835/mt6835_port_stm32.c` / `mt6835_port_stm32.h` | 固定板级 SPI3/PA0 适配：启动时读写探测、DMA1 Stream0/5 发收、片选时序、原始角度、传感器延迟和错误统计。 |
| `App/Protocols/JustFloat/justfloat.h` | UART/USB 的 JustFloat 帧宏：float32 通道后附 `+Inf` 分隔符；当前高速 USB 日志在 `app.c` 中显式排布。 |
| `App/README.md` | 参考工程随附的功能、命令、测试和历史实验记录。前面有当前结构说明，后面多轮历史参数需按时间辨别。 |
| `App/FOC/.gitkeep`、`App/Protocols/.gitkeep` | 空占位文件，不参与编译。 |

**阅读顺序建议：**`app.h → app.c` 的 `app_sample` → `foc.h → foc.c` 的 `foc_step` → `bsp_motor.c` 的 `bsp_motor_write/update` → `control.c`。遇到 HAL 寄存器再回头查板级驱动。

## B. 固件入口与 CubeMX 生成层

这层负责把芯片时钟、引脚和中断接到应用。`Core/Inc/*.h` 向其他模块提供对应外设句柄、函数与宏；`Core/Src/*.c` 实现初始化或回调。BSP 会在 CubeMX 初始设置后覆盖 ADC 同步采样、TIM8 触发和 DMA 细节，所以不能只看 `.ioc` 推断运行时寄存器。

| 文件 | 作用 |
|---|---|
| `Core/Src/main.c` / `Core/Inc/main.h` | 上电入口、168 MHz 时钟、外设初始化顺序、`app_init()`、前台 `app_poll()`、错误处理；头文件给出管脚名与公共入口。 |
| `Core/Src/stm32f4xx_it.c` / `Core/Inc/stm32f4xx_it.h` | 中断向量实现与声明。ADC DMA 半传输、SPI DMA 完成、TIM8 更新、UART、CAN、USB 在这里接到 BSP；硬故障先关功率。 |
| `Core/Src/stm32f4xx_hal_msp.c` | HAL 的 MCU 支持初始化：使能外设时钟、GPIO 复用、NVIC、DMA 关联。没有单独同名项目头文件。 |
| `Core/Src/system_stm32f4xx.c` | CMSIS 系统时钟变量和复位早期 `SystemInit`，供启动文件和时钟配置使用。 |
| `Core/Src/adc.c` / `Core/Inc/adc.h` | CubeMX 的 ADC1/ADC2 基础句柄与管脚初始化；最终双 ADC、扫描序列和 DMA 由 `bsp_adc.c` 再配置。 |
| `Core/Src/can.c` / `Core/Inc/can.h` | CAN1 基础波特率、句柄和 PB8/PB9 管脚；实际启动/过滤器在 `bsp_can.c`。 |
| `Core/Src/dma.c` / `Core/Inc/dma.h` | CubeMX 的 DMA 时钟和中断基础启用；采样与编码器 DMA 的详细寄存器由 BSP 管理。 |
| `Core/Src/gpio.c` / `Core/Inc/gpio.h` | 默认 GPIO 状态，尤其 PA0 编码器片选初始为高。 |
| `Core/Src/spi.c` / `Core/Inc/spi.h` | SPI3 模式、速率、PC10/11/12 复用与句柄，交给 MT6835 适配层使用。 |
| `Core/Src/tim.c` / `Core/Inc/tim.h` | TIM8 基础 PWM 和 PA7/PB0/PB1、PC6/PC7/PC8 六个栅极引脚；运行时精确时序由 `bsp_motor.c` 设定。 |
| `Core/Src/usart.c` / `Core/Inc/usart.h` | USART2 句柄、PA2/PA3 与 TX DMA 基础配置；`bsp_uart.c` 接管运行期收发。 |
| `Core/Src/syscalls.c` | newlib 的底层系统调用桩，支持 C 运行库链接；不承担电机控制。 |
| `Core/Src/sysmem.c` | 堆内存增长接口 `_sbrk`；裸机 C 运行库需要。 |
| `Core/Inc/stm32f4xx_hal_conf.h` | 本工程启用哪些 STM32 HAL 模块、时钟宏和公共配置。 |
| `startup_stm32f405xx.s` | 中断向量表、上电复位入口、数据段初始化及跳转到 `main`。 |
| `STM32F405XX_FLASH.ld` | Flash/RAM/CCMRAM 分区、栈堆和各节放置；保留 Flash 最后 128 KiB 作校准，`.usb_buffer` 放 64 KiB CCMRAM。 |
| `405_FOC.ioc` | CubeMX 的芯片、管脚、时钟和外设项目配置；需保留 USER CODE 并理解 BSP 的运行时覆盖。 |
| `CMakeLists.txt` | 固件目标和 App 源文件清单、可选 `FOC_CAPTURE`、链接库、实时源文件 O3 优化、ELF 后生成 BIN/HEX。 |
| `CMakePresets.json` | 通用 Debug/Release 预设和输出目录；本机 `CMakeUserPresets.json` 被 Git 忽略。 |
| `cmake/gcc-arm-none-eabi.cmake` | GNU ARM 编译器、Cortex-M4 硬浮点、链接脚本和编译参数。 |
| `cmake/starm-clang.cmake` | STM32 Clang 工具链的备选 CMake 配置；默认预设不用它。 |
| `cmake/stm32cubemx/CMakeLists.txt` | 把 CubeMX 的 Core、HAL、CMSIS、USB 中间件组合为构建目标。 |
| `.clangd` | 让 clangd 读取 Debug 编译数据库并查询本机 ARM GCC 头文件的编辑器配置；路径换机器时要改。 |
| `硬件PCB拓扑.md` | 参考板卡的电源、功率桥、采样、编码器、CAN 和 USB 拓扑及引脚推导；它是硬件资料，不是可执行代码。 |
| `docs/schematic/odrive-1.png`、`odrive-2.png`、`odrive-3.png` | 原仓库保留的三张原理图图片，供人工对照板卡；不参与编译，也不替代实物版本核对。 |
| `docs/FOC-从零读懂这个工程.md`、`docs/文件导览.md` | 本次移植新增的初学者教学主文档与逐文件索引。 |

## C. USB 设备层

| 文件 | 作用 |
|---|---|
| `USB_DEVICE/App/usb_device.c` / `usb_device.h` | 建立 USB 设备、注册 CDC 类与应用接口并开始枚举；声明初始化函数和设备句柄。 |

| `Middlewares/ST/STM32_USB_Device_Library/LICENSE.txt` | ST 中间件许可文本。 |

## E. 厂商驱动：每个文件族的用途

这些文件是参考工程包含的 ST HAL 与 ARM CMSIS。下面逐名列出**本次移植实际保留的文件族**；同一行的 `.h` 声明与 `.c` 实现配套，`_ex` 扩展功能。FOC 自己的采样/PWM 核心时序常直接访问寄存器，但仍依赖这些头文件和初始化/USB/CAN/Flash API。

| `Drivers/STM32F4xx_HAL_Driver/` 下的文件 | 作用 |
|---|---|
| `Inc/stm32f4xx_hal.h`、`Src/stm32f4xx_hal.c` | HAL 总入口与核心初始化、滴答时钟。 |
| `Inc/stm32f4xx_hal_def.h` | HAL 公共类型、状态码和宏。 |
| `Inc/stm32f4xx_hal_adc.h`、`Src/stm32f4xx_hal_adc.c` | ADC 句柄与普通 ADC 初始化/转换 API。 |
| `Inc/stm32f4xx_hal_adc_ex.h`、`Src/stm32f4xx_hal_adc_ex.c` | 多 ADC 等 ADC 扩展能力。 |
| `Inc/stm32f4xx_hal_can.h`、`Src/stm32f4xx_hal_can.c` | CAN 配置、过滤器、邮箱和收发中断。 |
| `Inc/stm32f4xx_hal_cortex.h`、`Src/stm32f4xx_hal_cortex.c` | NVIC、中断优先级和 Cortex 控制接口。 |
| `Inc/stm32f4xx_hal_dma.h`、`Src/stm32f4xx_hal_dma.c` | DMA 句柄、启动、停止与中断。 |
| `Inc/stm32f4xx_hal_dma_ex.h`、`Src/stm32f4xx_hal_dma_ex.c` | DMA 扩展控制。 |
| `Inc/stm32f4xx_hal_exti.h`、`Src/stm32f4xx_hal_exti.c` | 外部中断线配置与回调。 |
| `Inc/stm32f4xx_hal_flash.h`、`Src/stm32f4xx_hal_flash.c` | Flash 解锁、编程和状态。 |

| `Inc/stm32f4xx_hal_pwr.h`、`Src/stm32f4xx_hal_pwr.c` | 电源管理、低功耗和调压设置。 |
| `Inc/stm32f4xx_hal_pwr_ex.h`、`Src/stm32f4xx_hal_pwr_ex.c` | PWR 扩展功能。 |

| `Include/core_armv8mbl.h`、`core_armv8mml.h`、`core_armv81mml.h` | ARMv8/ARMv8.1-M 基础/主线架构通用定义；F405 不选用。 |

| `LICENSE.txt`、`Device/ST/STM32F4xx/LICENSE.txt` | CMSIS 和 ST 设备包许可文本。 |

库文件之所以多，是因为 CubeMX 拷贝了可复用驱动头文件；真正的业务入口始终在 `App/`，芯片初始化在 `Core/`，中断把两者接起来。初学者先把前四节读通，再在需要查某个寄存器或 HAL API 时进入这一节即可。
