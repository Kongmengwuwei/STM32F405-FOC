## 验证

主机入口（不访问串口）：

```powershell
python variants/m1-mt6835/tests/run_tests.py --cc gcc
```

40 个 C 配置和 5 个 Python 套件通过。覆盖启动加载/参数回滚、不同母线与采样频率、R/L 和磁编扫描、抗齿槽、多圈精度、M0 旧电机两种负载、配置身份、ADC 窗口、USB 解析/队列以及主机数据分析。C 编译使用 `-Wall -Wextra -Werror`，测试有子进程超时。

最终 ARM GCC 构建均通过：当前组合 Debug/Release、子目录独立 Debug、M0/TLE5012B/ZH3620-1/塑料臂、M1/MT6835/参考电机。产物放在本机 `build/cleanup/{Debug,Release,Standalone,M0,Reference}/`，上一轮实测 ELF 保留在原目录。

当前组合 Debug 使用 Flash 91,108 B、普通 RAM 17,000 B；Release Flash 79,628 B。USB 环形队列仍独占 64 KiB CCMRAM。与上一轮实测 Debug 相比，缓存和新的参数入口/共享保存函数增加 768 B Flash、24 B RAM；本次目标是减轻实时路径并减少维护重复，未声称固件整体变小。

前后 `foc_step` 反汇编中的 `vdiv` 指令数为 16→14，对应移走运行参数的两项采样频率除法。这是静态证据，不是实机总耗时或动态响应提升的测量。主机回归验证行为，Flash 写入去重未在本次执行新的板上擦写。

## 后续优化顺序

| 优先级 | 发现与建议 | 验证方式 |
| --- | --- | --- |
| 1 | 把实时耗时验收固定下来：已有 `motor_work_max`、PWM 写入余量和周期统计，缺少对全部运行/采集模式的统一时序验收。先量化再优化 SPI、遥测封帧和数学运算 | 固定供电与目标、记录最坏执行周期/写入计数器/丢帧；特别覆盖 10 kHz 静态采集和 20 kHz MT6835 |
| 2 | 当前普通测速仍依赖浮点机械位置差分。整数圈数解决了累计漂移，但很大的多圈位置仍会量化；可保留整数编码器计数，并用短窗口计数差或受带宽约束的角度观察器测速 | 跨零、多圈、单码低速与快速反向同时验证；不能只通过更重显示滤波判断改善 |
| 3 | 当前电流绝对比例来自板级常数，零偏可以自动测，增益不能靠 R/L 自整定可靠自校。先建立外部电流基准，再完善相间增益和逆变器电压偏差补偿 | 同一实际电流跨角度、正负方向与多电流水平比较，检查 R/L 的重复性和温度变化 |
| 4 | 自动适配目前覆盖电气参数，速度/位置增益仍按型号/负载选择。可增加有界短运动辨识惯量与摩擦，再独立验收机械环；抗齿槽表也应在目标低速/负载条件下重验 | 空载及实际负载分别检查响应、纹波和电流，保留失败回退；不直接把电流 Kp 比值当外环比例 |
| 5 | `app.c` 命令/遥测/保存调度较集中，台架脚本也有多套解析器。后续可抽出命令事务与共用解析模块；CAN 当前初始化接收但没有应用消费路径，可按实际用途关闭接收或实现完整协议 | 保持命令拒收计数、旧组帧布局及跨组丢序检测，逐个迁移脚本并跑现有回归 |

当前已实测的控制增益和抗齿槽表优先作为性能对照。上述需要新模型或实机数据的项目未在本次整理中直接替换控制算法。
