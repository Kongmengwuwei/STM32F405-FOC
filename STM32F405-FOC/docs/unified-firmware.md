# 统一固件：选择接口、编码器和电机

## 先分清四件事

`M0` 和 `M1` 是同一块驱动板上的两组三相**功率接口**，分别带有 PWM 定时器和电流采样路径。它们不是电机名称。电机用本体型号命名，例如 `ZH3620_1`；编码器按芯片型号命名，例如 `TLE5012B`。磁铁位置或三相接线改变，即使型号相同，电角度零点也可能改变，须更换安装编号并重新校准。

| CMake 选项 | 可选值 | 决定的内容 |
|---|---|---|
| `FOC_PORT` | `M0`、`M1` | PWM 引脚/定时器、ADC 路径、采样频率和接口保护上限 |
| `FOC_ENCODER` | `TLE5012B`、`MT6835` | SPI 帧格式、时钟模式、同步读取或 DMA、角度检查 |
| `FOC_MOTOR` | `ZH3620_1`、`REFERENCE_24V` | 极对数、资料参数、控制器的保守限值与环路初值 |
| `FOC_INSTALLATION_ID` | `1`–`15` | 当前磁铁、编码器、相线安装；参与 Flash 零点身份 |

顶层 `STM32F405-FOC/` 默认 `M0 + TLE5012B + ZH3620_1 + 1`。原参考项目的电机准确型号尚未提供，暂用 `REFERENCE_24V` 区分，**不要用 M1 称呼它**。该子目录独立构建时默认 `M1 + MT6835 + REFERENCE_24V + 1`。原来的 `variants/m1-mt6835` 目录名是历史来源；共享程序现在位于其中，顶层旧 `App/` 与 `Core/` 不参与当前构建。

## 图片中的 ZH3620-1

图片给出 12 槽、14 极（所以是 **7 极对**）、500 KV（标注 12 V/6000 rpm）、额定转矩 0.12 N·m、质量 77.4±1 g、工作环境 5–40 °C、空载电流 0.4 A、电压范围 7.4–12.4 V、最高电压 20 V、堵转电流 12 A。槽数、质量、KV、堵转电流等保存在电机参数头文件中供辨识和记录；控制算法真正使用的是极对数与经实机调试的电压、电流、速度、环路上限。**20 V 与 12 A 不是首次运行目标值。**

ZH3620-1 当前保守软件限值为母线 8–12.4 V、普通运行目标 Iq ±0.30 A、相电流绝对值 1.20 A 跳闸、速度 ±100 RPM。`cal` 单独使用 0.45 A 对齐目标、0.20 V 输出上限，每个方向扫描约 4 s；M0 在功率级使能后先用等占空比 PWM 复核电流零点。电机电阻 `0.12 Ω` 仍是两线万用表粗估，电感与磁链前馈关闭；板载采样绝对比例、栅极波形和硬件快速保护还未验收。2026-09-25 实机一次校准成功，短时转矩可使轴转动，但低速闭环尚未稳定，详见[诊断记录](zh3620-1-live-diagnosis-2026-09-24.md)。图片中的 12 A 堵转电流不是固件命令或保护值。

共用配置取**接口与电机两者的较严上限**。例如 ZH3620-1 接 M1 仍最多 12.4 V、0.30 A 普通目标、1.20 A 相跳闸；原参考电机接 M0 仍被 M0 接口限制在 14 V、0.30 A、1.20 A。交叉组合只是编译配置，以上数值并非它们的实机验收结果。`REFERENCE_24V` 的资料与名称待确认，当前保留旧工程参数供对照，不建议用它驱动未知电机。

## 构建和烧录

在 `STM32F405-FOC/` 构建默认配置：

```sh
cmake --preset Debug
cmake --build --preset Debug
```

输出为 `build/Debug/STM32F405-FOC.elf`、`.bin`、`.hex`。切换任一选择时使用**独立构建目录**，例如把 ZH3620-1 和 TLE5012B 接到 M1：

```sh
cmake --preset Debug -B build/zh3620-m1-tle -DFOC_PORT=M1 -DFOC_ENCODER=TLE5012B -DFOC_MOTOR=ZH3620_1 -DFOC_INSTALLATION_ID=2
cmake --build build/zh3620-m1-tle
```

检查 CMake 输出的四个选择和 ELF 路径，再用 ST-Link 烧录**这个** ELF。切换回默认构建目录时再运行默认预设；VS Code 默认烧录任务只指向 `build/Debug/STM32F405-FOC.elf`。编码器两种驱动都针对板上 SPI3/PA0 片选，SPI3 引脚 PC10/PC11/PC12。M0 三相采样用 PC0/PC1、TIM1 10 kHz；M1 用 PC3/PC2、TIM8 20 kHz。PA6 是母线采样。先核对实物丝印与磁编码器供电，切换接口时重接三相并检查相序。

目前 M0/TLE、M0/MT、M1/TLE、M1/MT 四个接口/编码器组合都能编译；默认 M0/TLE、原参考 M1/MT 的共用命令经过主机测试。**交叉组合仍需要在实际硬件上测 SPI/ADC 采样时序、栅极和保护，不应仅凭编译通过带负载运行。**

## 程序层次和新增型号

| 文件 | 改动范围 |
|---|---|
| `App/Config/foc_port.h` | 新功率接口的计时、采样、电气上限 |
| `App/Config/foc_encoder_profile.h`、`App/Hardware/encoder/bsp_encoder_*.c` | 新编码器的精度、速度检查和角度读取；错误帧返回 NaN |
| `App/Config/foc_motor.h` | 新电机的真实型号、极对数、实测绕组值、保守工作限值及调参初值 |
| `App/Config/foc_profile.h` | 四项选择的合法性和上限合成、Flash 身份 |
| `App/Control/app.c`、`control.c`、`App/FOC/foc.c` | 共用 USB/UART/CAN、命令、外环、电流环、SVPWM 与故障处理；新增电机通常不用复制这些文件 |

校准 Flash 记录 v3 同时检查接口、电机型号、编码器型号、安装编号与极对数。早期 v1/v2 记录无法证明这些信息，所以本版不会复用。每个组合上电先静止估计电流零偏，**都不自动转动**。首次在轴可自由转动时发送 `cal`，成功保存后才接受运行目标。重装传感器、改相线或换电机时将安装编号加 1 并重新 `cal`；编号 1–15 用尽后需设计更长的身份字段，不能随意复用旧编号。当前 `.ioc` 尚不能一键重生成所有条件编译分支，修改 CubeMX 生成文件时同步核对手写代码。

## USB 与上位机

原生 USB 是 CDC 虚拟串口，产品字符串包含电机型号、编码器与功率接口；USART2 是 PA2/PA3 的独立串口。VOFA+ 选对应 COM、Serial、2000000 baud、8N1、无流控，协议选 JustFloat，并打开 DTR。CDC 里波特率只是主机设置，不改变 USB 线速。USB 输出二进制波形，没有文字 ACK；`hello` 的文本只经 USART2 返回，列出接口、编码器、电机、安装编号及状态，便于核对烧录组合。文本命令需以真实 CR、LF 或 CRLF 结束。

USB 每帧为 12 个小端 float32 加 `+Inf` 帧尾，共 52 字节。`send 0` 看 ADC 原始码、母线电压和原始编码器角度；`send 1` 看 B/C 相电流、电角度、Iq 目标与电流环；`send 2` 看输出电压和 PWM；`send 3` 看位置、速度、Iq。M0 以 10 kHz 输出约 520 kB/s；M1 以 20 kHz 输出约 1.04 MB/s。第 0、1 通道把时间、状态、序号、组号编码到 float32 的位里，不直接作为普通曲线。`send 3` 的通道 7 是 FOC 滤波转速、8 是目标转速、9 是实测 Iq；其余表见[台架工具说明](../variants/m1-mt6835/tools/bench/README.md)。默认 M0 完整性校验可用 `python tests/capture_usb.py COM端口 --sample-hz 10000 --seconds 30`（在共用固件目录运行）。原 `bench.py run` 工况脚本仍按参考电机编排，不能直接驱动 ZH3620-1。

| 命令 | 用途 | ZH3620-1 当前范围 |
|---|---|---|
| `send 0`～`send 3` | 选择 USB 遥测组 | 0–3 |
| `cal` | 静止待机时低电压扫描并存零点 | 首次必须显式发送 |
| `Iq 0.05` | 电流目标，单位 A | ±0.30 A |
| `rpm 10` | 速度目标，单位 RPM | ±100 RPM |
| `pos 90` | 多圈位置目标，单位机械度 | ±1e6°（位置外环限速 30 RPM） |
| `zero` | 静止时将当前位置定义为 0° | 待机时 |
| `stop` | 立即关闭功率级并清除运行目标 | 随时 |
| `clear` | 故障原因消失后清锁存，不自动启动 | 故障时 |

`Iq`、`rpm` 和 `pos` 运行时均须在 200 ms 内重发目标，建议每 50–100 ms 重发。超时会报 `FOC_UART` 并关断，故障消失后也不会自动启动；只在 VOFA+ 手动发一次目标，约 200 ms 后停机是预期行为。`Iq 0` 在待机时不启动；`rpm 0` 和 `pos 0` 则是持续闭环请求。当前 ZH3620-1 的速度和位置环仍待实机整定，不宜直接用 VOFA 长时间连续运行。实机上电和渐进测试按[ZH3620-1 首测清单](zh3620-1-first-test.md)执行。
