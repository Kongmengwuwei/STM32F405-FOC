# FOC 程序架构

CubeMX 生成的 `Core/` 与 `Drivers/` 负责启动和 MCU 外设。手写控制代码放在 `App/`，由顶层 `CMakeLists.txt` 纳入构建，避免在重新生成 CubeMX 代码时丢失算法。

## 数据与控制边界

1. **板卡层**：配置引脚、时钟、PWM、ADC、编码器总线和故障输入；仅输出带时间戳的原始采样及明确的硬件状态。
2. **器件层**：按具体磁编码器型号及实际传输接口解码数据并检查诊断状态。不能仅因总线上有返回值就认定角度有效。
3. **测量层**：电压/电流比例、零点、方向校准；角度范围、时效和速度合理性检查。输出明确的有效/故障状态。
4. **控制层**：Clarke/Park、电流 PI、逆 Park、调制和限幅；只消费有效测量，计算过程不访问 HAL 或阻塞总线。
5. **运行状态层**：上电保持未使能；校准、待机、运行、故障分开。故障需锁存并明确复位，不能因下一帧数据正常而自动恢复输出。

当前算法层包含坐标变换、零点校准、测量换算、角度可信度检查、d/q 电流 PI、SVPWM 与驱动状态机；这些模块不访问 HAL。AS5600 与 AS5047P 的协议代码保留作历史参考，已从当前固件构建移除。TLE5012B 使用 SPI3 模式 1、16 位字与 PA0 片选，安全字 CRC 和状态位均需通过。`board_adc.c` 使用 ADC1 的 TIM1 TRGO 注入序列同步采集 M0 B/C 相，ADC2 读取母线电压。`board_pwm_m0.c` 配置 TIM1 中心对齐 10 kHz 互补 PWM、死区及固定采样点。六路输出上电默认关闭，故障时先清 TIM1 MOE，再把栅极输入切回低电平 GPIO。

`foc_current_zero.c` 在驱动关闭期间对 M0 B/C 相采集 256 组定时同步样本，检查原始范围与窗口跨度，得到两路独立零点；实测跨度约 10–13 ADC 计数。零点进入 `foc_current_loop.c`。`main.c` 暂时承载上板试验的命令门控、对齐、方向验证、一次性转矩脉冲与诊断变量；下一阶段应将这段试验编排抽到独立应用模块，并把参数与故障事件做成明确接口。

系统时钟已由 16 MHz HSI 配 PLL 提至 168 MHz，APB1 为 42 MHz、APB2 为 84 MHz。外设初始化仍由 `App/` 板卡层执行。**`.ioc` 目前仍是最初的 16 MHz 模板**；直接重新生成 CubeMX 代码会覆盖 `SystemClock_Config()` 等手工修改，重生成前必须同步 `.ioc` 与板卡配置，或将时钟配置移入用户代码区域。上电自动运行的外环位于纯算法模块 `foc_speed_loop.c`，启动和故障门控仍在 `main.c` 的试验编排中。

## 时间约束

电流环由 TIM1 在每个 100 µs PWM 周期固定相位触发 ADC1，ADC 完成中断直接运行控制计算；中断内不做 SPI 传输、日志、动态分配或无界等待。主循环读取编码器，试验运行时每 1 ms 更新一次；样本超过 2.5 ms 即关断。已记录 0.3 秒试验中控制回调最慢约 23 µs。高速运行前还需实现速度估计与角度延迟补偿。

模式 0 下的低 14 位结论源于错误采样相位，已作废。模式 1 下的 TLE5012B 响应符合低 15 位、32768 计数/圈；手转角度连续且安全字 CRC 正确。M0 在 12 V、1 A 限流条件下完成短时对齐与 0.2 A 目标 q 轴电流试验。用户提出的上电自动 60 rpm 已编码并试烧录，但实物目前只达到约 3 rpm 或触发过流，未达到验收；结果和待查项见 `m0-torque-bring-up.md`。断线注入、示波器波形、温升、负载与长期稳定性也未验收。
