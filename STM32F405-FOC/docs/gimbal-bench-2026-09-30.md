# 双轴云台烧录与实机位置测试（2026-09-30）

已用 ST-Link 对当前云台固件烧录、读回校验并复位，USB CDC COM8 持续收到约 1 kHz 的双轴反馈。**目前未通过双轴位置控制验收**：M0 尚无有效校准，M1 正向小角度与回零通过粗定位门槛，反向定位仍存在卡滞/摆动。结束时发送 `stop`，再以 USB 和 ST-Link 检查两路关闭。

## 保留在板上的最终配置

| 参数 | M0 水平轴 | M1 竖直轴 |
|---|---|---|
| 位置目标 / 实际越界边界 | ±85° / ±90° | ±55° / ±60° |
| 轨迹速度 / 加减速 | 5 RPM / 10 RPM/s | 同 M0 |
| 外环电流 / 相电流停机阈值 | ±0.60 A / 1.50 A | 同 M0 |
| 校准电流 / 电压上限 | 0.25 A / 0.10 V | 0.45 A / 0.20 V |
| 位置 P / 速度 P / 速度 I | 0.50 / 0.08 / 0.20 | 0.40 / 0.12 / 0.12 |
| 外环速度滤波时间常数 | 8 ms | 8 ms |

`FOC_GIMBAL=ON`、`FOC_DUAL=ON`、`FOC_PROTECTION=WARN`，但云台强制保护继续生效；10 RPM 超速停机现在也覆盖校准和 `test`。软件限位不重置于 `zero`、`clear`。最终 ELF 的 SHA-256：`935cccccf690e32d7030298bc019f2fec3ac47d903799f995f139874bea2db6f`。

## 静止反馈与清故障修复

第一次烧录后 M0 在功率级关闭时锁定 `FOC_SENSOR`，后续连续 SPI 反馈有效。重启 SPI/ADC 采样再清除故障后，仍会遇到最初少量 SPI1 坏帧。尝试在前台关中断重置两路控制器时，又触发采样间隔保护 `FOC_ADC`，该处理已撤销。

最终将单轴故障的 `clear` 请求交给采样中断，在完成该周期的采样读取后重置控制器；持续有效的后台 SPI/ADC 不再重启。校准、物理行程中心与显示零点保留，输出继续关闭并重新估计静止零偏。共用采样故障仍走完整硬件重启。多轮静止检查通过；启动坏帧的硬件根因尚未确认，没有取消 CRC、传感器状态或有效采样检查，也没有引入带电坏帧容错。

## 运动结果

### M0 校准

原 0.45 A / 0.20 V 与中间 0.35 A / 0.15 V 试验在初始对齐/开始扫角时出现约 20 RPM 的短时运动，PC 脚本检测后立即 `stop`。前期部分数据伴随用户手动转轴，不用于判断闭环效果；用户恢复结构与接线到松弛中间后，未手转的复测仍出现快动。

保留的 0.25 A / 0.10 V 在两次试验中均不能完成一电角周扫角。最终这一轮：

- 运行约 5.55 秒后，正向扫角检查触发 `FOC_ALIGNMENT=5`。
- ST-Link 读到 `ticks=55000`、`forward=-0.0989°`；当前 7 极对一电角周要求机械约 51.4°，允许验证范围约 41.1°～61.7°。
- USB 位置范围 −0.297°～+0.308°，母线 11.738～11.938 V，电流矢量估计峰值约 0.632 A。
- `calibrated=false`，未写入无效校准，因此未下发 M0 位置目标，也未测试双轴同时定位。

这些证据说明当前带载与保守参数下无法完成校准，不能直接证明电机、驱动板或机械负载中的哪一项是根因。下一步宜先暂时解除 L 形结构给 M0 的负载，检查转动阻力与线束牵扯，再在相线和编码器安装保持不变的条件下完成单轴校准；随后重新带载验证位置。

### M1 位置

板上加载了有效 M1 校准记录，电角度零点约 4.40067 rad、方向 −1。本次没有覆盖该记录。

完整 `+3° → −3° → 0°` 测试在负向阶段未通过：原保守增益存在摆动；增加速度 P、减小 I 后负向进展偏慢；加入低速滤波与中间增益后仍有约 2° 的负向误差/过冲。最新相同 M1 参数的负向测试位置最低约 −5.30°，8 秒末约 −4.97°，目标为 −3°，因此未继续把该轮算作通过。

最终板上固件另做 `+3° → 0°` 测试，每段观察 8 秒，判定门槛为末端误差不超过 1°：

- +3° 阶段末端约 +3.50°，峰值约 +3.58°。
- 回 0° 阶段末端约 +0.275°。
- M1 电流矢量估计峰值约 0.690 A，母线 11.752～11.952 V；该运动测试期间两轴故障码均为 0。
- 脚本确认停机后关闭串口。以上仅说明粗定位方向与回零可工作，不代表反向定位、精度、长时间保持或全行程通过。

负向卡滞、摆动及停机后的被动位移提示需检查竖直轴重心平衡、摩擦/线束作用，再结合有效校准、电流采样和外环参数继续区分原因；不能仅据此认定是增益问题。静止电流估计也存在偶发尖峰，未经电流探头复核，不把这些数值当作绝对电流精度证据。

## 手动转轴与限位

测试间用户手动转过两轴，触发 `FOC_POSITION=12`。该时段不计入控制响应结论。ST-Link 确认 TIM1/TIM8 三相输出已关闭，软件未自动清掉限位。用户确认结构和接线恢复松弛中间后才复位建立新中心。之后的无手转数据单独保存。每次 MCU 复位仍须先确认接线没有被绕紧。

最终 +3°/回零测试结束并收到停机反馈后，保存数据期间的位置又大幅变化；最后 ST-Link 读到 M0/M1 均为 `FOC_FAULT`、故障码 12，M0 行程约 −158.0°、M1 约 +55.7°，两路已越界锁定。此次变化的外部原因尚未再向用户确认，因此不将它归因于控制响应，也不自动复位或清除。最后 PWM CCER 为 TIM1 `0x1000`（仅保留 ADC 触发通道）、TIM8 `0x0`，两路三相输出均关闭。继续通电运动前需先将结构和接线恢复松弛中间。

## 数据与重复方法

原始 CSV、逐次结果 JSON 和最终 ST-Link 寄存器日志位于 `build/gimbal-20260930/`（本地测试产物，未纳入 Git）：

- `final/cal-m0.csv`、`final/cal-m0.json`：最终 M0 校准失败。
- `final/cal-failure-snapshot/snapshot.json`：失败阶段、校准有效性与 PWM 关闭证据。
- `revision5/pos-m1.csv`、`revision5/pos-m1.json`：无手转的负向定位失败，M1 参数与最终固件相同。
- `final/pos-m1-positive.csv`、`final/pos-m1-positive.json`：最终固件的 +3°/回零测试。
- `final/stop-check/idle.json`、`final/stop-snapshot/snapshot.json`：结束时状态和输出检查。

`tools/gimbal_bench.py` 全程监看电流、速度、母线、位置和状态；异常立即发送 `stop`，退出前等待停机反馈。限时测试不会自动重复运动，不清零或扩大行程。例：

```powershell
python tools/gimbal_bench.py COM8 idle --out ../../build/gimbal-check
python tools/gimbal_bench.py COM8 clear --out ../../build/gimbal-check
python tools/gimbal_bench.py COM8 pos-m1 --out ../../build/gimbal-check
python tools/gimbal_snapshot.py ../../build/Debug/STM32F405-FOC.elf ../../build/gimbal-check/snapshot
```

以上在 `variants/m1-mt6835/` 目录运行，必须先确认供电限流、物理行程和校准状态，运动期间不要手转。双轴同时定位留待 M0 校准和两路单轴定位通过后进行。最终 ARM 编译与 WARN/TRIP 各 9 项主机测试通过，共 18 项；主机模型通过不替代本次实机未通过项。
