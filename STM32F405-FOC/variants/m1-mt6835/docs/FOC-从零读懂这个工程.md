# 从零读懂这个 FOC 工程

**版本说明（2026-09-27）：** 当前各型号共用一套代码，默认 M0/TLE5012B/ZH3620-1，默认策略为 WARN。本文的参考电机数值、1 A/s 斜坡和跳闸说明对应原参考配置及可选 TRIP 策略；WARN 已取消命令限幅、通信超时关断及阈值跳闸，具体更新与文件职责见[台架告警模式](../../../docs/bench-warning-mode.md)和[统一固件指南](../../../docs/unified-firmware.md)。历史参数不能直接当作默认构建参数。

这是一份按**此 M1 子工程代码**编写的阅读和实践指南。固件从参考目录 `F405_FOC_Fork` 的 `2ac684d` 版本移植而来；应用算法和板级驱动保持该版本的实现。仓库默认固件目录 `STM32F405-FOC/` 使用 M0/TLE5012B，本文只讲解可选的 M1/MT6835 方案。参考目录中的说明有多轮历史实验记录，历史数值不能自动视为当前固件的配置；以下参数都以此子工程的代码为准。

读完后，应能回答四个问题：电机为什么要测角度与电流；50 µs 内发生了什么；`Iq`、`rpm`、`pos` 怎样变成 PWM；为什么出错时要立即关断功率级。逐文件索引见文末链接的[文件导览](文件导览.md)。

## 1. 先建立一张地图

电机是三相永磁同步电机。直流电源只提供母线电压，三相逆变桥靠六路栅极信号把它变成方向与幅值不断变化的三相电压。转子磁铁的位置由 MT6835 磁编码器测出；B、C 两相电流由分流电阻和 ADC 测出，A 相电流由 `ia = -ib - ic` 算出。控制器每 **50 µs** 做一次计算，即 **20 kHz 电流环**。

```text
上位机目标 Iq / rpm / pos
          │
          ▼
  位置 P → 速度 PI（每 1 ms）
          │ Iq_ref，单位 A
          ▼
  电流 PI（每 50 µs） ← MT6835 角度 + B/C 相电流
          │ Ud / Uq，单位 V
          ▼
  逆 Park → 居中 SVPWM → TIM8 三相互补 PWM
          │
          ▼
  功率桥 → 电机 → 编码器、电流采样，回到控制器
```

**内环**回答“实际电流怎样跟上目标电流”，**外环**回答“为了达到目标转速或位置，应该要多少 q 轴电流”。q 轴电流主要产生转矩；d 轴电流主要沿转子磁场方向，本项目把 `Id_ref` 设为 0。通信、日志和 CAN 是外围功能，不在电流反馈的必经路径上。

## 2. 看懂单位与角度

磁编码器给的是机械角 `θm`，一圈 360°。这个电机按 **7 极对**计算，因此电角 `θe` 一圈对应机械角约 `360/7 = 51.43°`：

```text
θe = wrap(direction × 7 × θm - electrical_zero)
```

`direction` 和 `electrical_zero` 由校准得到，保存到 Flash。`wrap` 把角度折回一个电周期。代码还用 `angle += 0.52° × cos(2 × angle)` 修正此台磁铁安装测得的二次谐波；换电机、磁铁或编码器后，此系数必须重新核对。`foc.c` 会把编码器读数推到采样时刻，再预测到下一次 PWM 生效中心，以减轻采样、计算和执行延迟造成的相位误差。

采样的 ADC 数字先换算为电压：`Vadc = raw × 3.3/4095`。B、C 电流在静止时分别求出零偏，然后按标称放大器增益换算：`Ib = (Vb - B_offset) × 50`，`Ic = (Vc - C_offset) × 50`，单位 A。这个 **50 A/V 是标称值**，并不代表已经用电流探头标定。母线电压按电阻分压比 `41.2/2.2` 还原。

Clarke 变换把三相电流放到静止的二维坐标系：

```text
Ia = -Ib - Ic
Iα = Ia
Iβ = (Ib - Ic) / √3
```

Park 变换再随着转子转动坐标系：

```text
Id = Iα cosθe + Iβ sinθe
Iq = -Iα sinθe + Iβ cosθe
```

这样，原来随时间起伏的三相正弦电流变成相对稳定的 `Id` 与 `Iq`，就能分别用 PI 控制。若只记一个直觉：**先测电流和角度，再把电流投影到跟着转子转的坐标系，控制完再投影回三相**。

## 3. 50 µs 内的真实执行顺序

`Core/Src/main.c` 初始化时钟、GPIO、DMA、TIM8、双 ADC、SPI3、USART2、CAN1 和 USB，然后调用 `app_init()`。主循环只处理命令、Flash 保存和 USB 队列；实时控制由中断推进，主循环睡眠不会暂停 FOC。

1. **TIM8 生成中心对齐 PWM 和采样触发。** 168 MHz 计数时钟，`ARR=4200`、`RCR=1`，一个控制周期为 50 µs。CH1～CH3 是三相互补 PWM，CH4 在固定位置通过 TRGO 触发 ADC。`bsp_motor.c` 在谷底统一使新 CCR 生效，避免三相在同一周期采用不同版本的命令。
2. **ADC 同时采 B/C 相。** ADC1 的 PC3/IN13 是 B 相，ADC2 的 PC2/IN12 是 C 相。双 ADC 的第一个规则序列样本由 DMA2 Stream0 读出；半传输中断记录时间戳并调用 `mt6835_start()`，让 SPI 读角度与第二个 ADC 样本重叠。第二个样本是 PA6/IN6 母线电压。
3. **SPI DMA 读取 MT6835。** SPI3 使用 PC10/PC11/PC12，PA0 为片选，模式 3、约 10.5 MHz。DMA1 Stream5 送 6 字节命令，Stream0 收 6 字节。接收中断调用 `mt6835_finish()` 验证 CRC 与传感器状态，随后 `bsp_adc_read()` 发布完整电压快照。
4. **`app_sample()` 算电流并写下一周期 PWM。** 它先检查当前采样窗口，再调用 `foc_step()`；结果经过 `foc_window()` 二次检查，交给 `bsp_motor_write()` 写 TIM8 预装载。接着 `foc_outer_step()` 以 1 ms 节拍更新外环；日志入队和统计最后执行。
5. **TIM8 谷底更新中断**运行 `bsp_motor_update()`：检查是否赶上截止时间，再切换栅极模式，使三相预装载同时生效。未及时提交或采样周期异常时立即关断。

这条链在代码中的入口依次是 `stm32f4xx_it.c` 的 `DMA2_Stream0_IRQHandler` → `DMA1_Stream0_IRQHandler` → `app_sample` → `foc_step` → `bsp_motor_write` → `TIM8_UP_TIM13_IRQHandler`。TIM5 提供 1 MHz 微秒时间戳，DWT 计数器统计控制路径耗时。ADC 和 SPI 的 DMA 搬运不让 CPU 逐字节等待，但中断处理、CRC 和 FOC 数学仍消耗 CPU 时间。

## 4. 启动、校准和状态机

状态定义在 `foc.h`。核心路径如下：

```text
上电 → OFFSET（功率关断，求电流零偏）
                   ├─ Flash 校准记录有效 → IDLE
                   └─ 无有效记录 → PRECHARGE → CALIBRATE → SAVE → IDLE
IDLE + Iq/rpm/pos 命令 → PRECHARGE → RUN
RUN + stop → IDLE
任何保护失败 → FAULT；clear 只在条件恢复后回到 IDLE，不自动启动
```

`OFFSET` 要求转子连续静止约 200 ms，再取 **2048 对** B/C 样本求均值和方差。零偏应处在 1.4～1.9 V，噪声过大则报 `FOC_ZERO`。零偏每次上电重测，不写入 Flash。

如果 Flash 扇区 11 的记录有效，启动时复用电角零点与方向；否则自动开始第一次对齐。`PRECHARGE` 保持约 2 ms 三低侧导通。`CALIBRATE` 用最高 0.6 V 对齐电压，先缓升，再正向扫一个电周期、反向扫回，通过实际机械位移判定方向，最后统计静止角度求电角零点。整个校准程序约 `120000/20000 = 6 s`。失去预期位移或终点不稳定会报 `FOC_ALIGNMENT`。`SAVE` 先停止采集和栅极输出，再把校准记录写入 Flash 并读回校验；用户用 `cal` 可在静止待机时重校准。

Flash 记录在 `0x080E0000`，含版本、极对数、方向、零点、校验和、魔数。链接脚本把可执行固件限制在前 **896 KiB**，留下最后 128 KiB 扇区保存记录。擦写扇区会清除旧校准，换电机或传感器后需要重新校准。

## 5. `foc_step()` 如何把电流变成 PWM

每次进入 `foc_step()`，代码先检查角度、ADC 和采样延迟是否有限且可信；运行或校准时还检查母线 **8～36 V**。它更新机械角连续位置与编码器转速，完成上述电流坐标变换后，再检查三相电流峰值是否达到 **10 A**、转速是否达到 **9400 RPM**。任何检查失败都进入故障状态并关断。

在 `RUN` 中，q 轴目标先以 **1 A/s** 从上一命令值逼近新 `Iq` 命令，每个 50 µs 周期最多移动 `0.00005 A`。如果当前是速度或位置模式，1 kHz 外环给出的 `Iq_ref` 会覆盖这条转矩命令斜坡。电流 PI 的误差为 `ed = 0 - Id`、`eq = Iq_ref - Iq`。代码标称 PI 带宽 600 Hz，`Kp≈0.1885 V/A`、每采样步积分增量 `KiTs≈0.02262 V/A`；另外使用电机电阻、电感和磁链的标称值作速度前馈。这些参数是参考电机的调试值，不应直接推广到另一台电机。

得到 `Ud/Uq` 后，先按 `Vbus/√3` 限制电压矢量长度，再做逆 Park，把旋转坐标电压变回静止的 `Uα/Uβ`：`Uα = Ud·cosθe - Uq·sinθe`，`Uβ = Ud·sinθe + Uq·cosθe`。三相电压是 `Ua=Uα`、`Ub=-Uα/2+√3·Uβ/2`、`Uc=-Uα/2-√3·Uβ/2`。`foc_modulate()` 加入共同的零序偏移，得到居中 SVPWM 占空比。**三相一起平移不会改变线电压**，但能给 B/C 低侧采样留出更多时间。若窗口仍不够，才把矢量整体缩小。`foc_window()` 再检查每相开关沿与 ADC 孔径、死区和模拟建立时间的间隔。实际缩放量回传给 PI 作抗饱和反算，避免执行器已到极限而积分器继续累积。

PWM 写入的是 `CCR1/2/3` 预装载，下一谷底才生效。`bsp_motor_write()` 还要求处于正确计数半周且 `CNT≥600`，否则视为错过截止时间。窗口计算中的 500 ns 死区、3 µs 建立时间和附加触发预算来自参考设计，**数字时间检查不能代替示波器对模拟采样质量的核验**。

## 6. 三种用户模式

| 命令 | 它控制什么 | 实际进入电流环的目标 |
|---|---|---|
| `Iq 0.20` | 转矩模式，目标 q 轴电流 0.20 A | 命令经过 1 A/s 斜坡形成 `Iq_ref` |
| `rpm 500` | 速度模式，目标机械转速 500 RPM | 速度 PI 每 1 ms 算 `Iq_ref` |
| `pos 720` | 位置模式，目标相对零点的两整圈 | 位置 P 先算速度目标，速度 PI 再算 `Iq_ref` |

三种命令都经 `control.c` 的 `start()` 检查校准与零偏，再走同一条 `PRECHARGE → RUN` 联锁。`Iq 0` 在待机时不会启动，运行中则保持零目标电流环；`rpm 0` 和 `pos 0` 是真实的闭环保持请求。`stop` 立即关断并清掉外环积分器。`zero` 只能在待机且静止时把当前位置定义为 0°。

外环每 1 ms 更新一次。速度 PI 使用 `Kp=0.005 A/RPM`、`Ki=0.01 A/(RPM·s)`，输出限制为 ±5 A；位置 P 使用 `4 RPM/°`，其速度目标限制为 ±100 RPM，再进入速度 PI。目标来自上位机，因此速度和位置模式要求在 **200 ms** 内持续收到新目标，否则 `FOC_UART` 故障停机；纯转矩模式没有该看门狗。这些数值是代码当前配置，并非自动整定结果。

**走一遍例子：**上位机发送 `rpm 500\r\n`。前台解析为速度目标，通过临界区发布；下一采样周期开始功率联锁，2 ms 后进入 `RUN`。外环每 1 ms 比较目标 500 RPM 与编码器测得速度，算出需要的 `Iq_ref`。20 kHz 内环比较它与 ADC 算出的 `Iq`，产生 `Uq`，再由 SVPWM 输出三相占空比。负载增大导致转速下降时，速度误差会增大，外环请求更多 q 轴电流；电流环负责真正把电流跟上去。

## 7. 命令、日志与 CAN

USART2 在 PA2/PA3，**2 Mbps、8N1**。USB 是 CDC 虚拟串口。两路都能接收以 CR、LF 或 CRLF 结尾的 ASCII 命令；`hello` 文本回复只从 UART 发，USB 保持纯二进制数据流。命令有 `Iq ±5 A`、`rpm ±9400`、`pos ±1000000°`、`zero`、`stop`、`clear`、`cal`、`send 0`～`send 3`、`hello`。数字允许整数或最多两位小数。`clear` 只清已经消失的故障，并不会重新启动功率。

UART 日志每 **10 个采样周期**发送一次，即 **2 kHz**；一帧为 15 个 32 位浮点数，加 `+Inf` 帧尾，共 64 字节。包含 `Id/Iq`、ADC 电压、序号、RPM、母线电压、目标电流、电角度、`Ud/Uq`、三相占空比和状态。UART 发送用双缓冲 DMA，写接口只保证已排队，不保证 PC 已收到。

USB 在连接并打开 DTR 后，每个采样周期尝试发送 **12 个 float32 + `+Inf` 帧尾 = 52 字节**，满速约 1.04 MB/s。前两个 32 位字按**位**打包时间/状态和序号/组号，虽然用 float 容器传输，解析时应还原原始字节，不能把它们当普通数值浮点读。`send 0..3` 切换余下 10 个通道：0 原始 ADC/角度；1 电流与 PI；2 电压/PWM/窗口；3 目标与机械响应。具体下标见 [`tools/bench/README.md`](../tools/bench/README.md)。USB 队列放在 64 KiB CCMRAM，溢出会锁存，重新枚举后清除；高速记录需要 PC 持续接收。

CAN1 使用 PB8/PB9、1 Mbps，驱动提供非阻塞收发和 15 帧有效容量的接收队列；**当前应用没有把 CAN 帧解析成电机控制命令**。`tools/bench` 可以解析 USB 日志、发现设备并做台架工况，但自动工况会实际驱动电机，阅读与无硬件验证阶段只需运行 `selftest.py`。

## 8. 保护为什么分散在多个文件

保护靠近故障来源：`mt6835` 发现 CRC/状态/DMA 错误就给出无效角度；`bsp_adc` 发现溢出或 DMA 错误就停止采样并给出无效值；`foc_step` 检查传感器、电流、母线与超速；`bsp_motor` 检查 PWM 提交时刻和采样周期；`app_fault()` 统一立即关栅极并锁存故障。中断优先级较高的错误还能抢占普通 FOC 计算，`bsp_motor_update()` 防止旧的预装载在故障后重新打开栅极。

`FOC_FAULT` 不会自行恢复到运行。前台可以为继续诊断而重新启动**采集链路**，这不等于重新使能功率。`clear` 还要确认近期样本、母线、编码器、速度和近零电流条件已经恢复，之后才回待机。`FOC_CAPTURE` 是可选诊断构建，能存 2048 个 48 字节样本，采满即关断；普通 Debug/Release 不含这块记录缓冲。

## 9. 如何在本仓库学习和验证

1. 先读本章和[逐文件导览](文件导览.md)，沿 `main.c → app_init → 中断 → app_sample → foc_step → bsp_motor_write` 找一遍函数。每看到一个量，写下**单位、更新频率、由谁写入**。
2. 在此 M1 子工程目录用 CMake/Ninja 和 ARM GCC 构建：`cmake --preset Debug`、`cmake --build --preset Debug`；要看实际运行时序应使用 `Release`。本机可自行创建被 Git 忽略的 `CMakeUserPresets.json`。实时路径即使在 Debug 构建中也按 `-O3` 优化，调试器里的单步和局部变量可能与源代码顺序不同。链接后的 `405_FOC.elf/.hex/.bin` 在此目录的 `build/<配置>/`。
3. 按 [`tests/README.md`](../tests/README.md) 的命令运行 6 个主机 C 测试，再运行 `python tools/bench/selftest.py`。这些测试覆盖公式、命令、队列与状态机的模拟条件；它们不能验证真实中断抢占、栅极波形或模拟电流精度。
4. 上板前核对[硬件拓扑](../硬件PCB拓扑.md)、本机接线、MT6835、7 极对、B/C 电流极性、ADC 增益、36 V 母线界限、10 A 相峰值保护和 Flash 扇区。参考代码针对 M1；原工程曾使用 M0 和别的编码器，**不能把新固件当作原接线的直接替代品**。
5. 理解数据再调参：先确认角度方向和静止零偏，再看三相电流及 `Id/Iq`，接着检查 PWM/采样窗口，最后调速度 PI、位置 P。参考工程的上板报告是它自己的台架记录；本次移植只完成编译与主机测试，没有在本项目硬件上重新烧录或验收。
